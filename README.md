## แหล่งข้อมูล

```
GET https://api-hdc.moph.go.th/v1/reports/province/data/{EXCHANGE_ID}
```

- `EXCHANGE_ID = 71e49e4b61aafee17761601c506d5f85`
  คือรายงาน **"2.1 ความครอบคลุมของเด็กอายุครบ 2 ปี ที่ได้รับวัคซีนแต่ละชนิด รายไตรมาส"**
  (`source_file: epi/epi_2.php`, ตารางสรุป `s_epi2`)
- Headers ที่ต้องส่ง: `domain: ksn`, `authorization: Bearer null`, `referer: https://hdc.moph.go.th/`
- Params หลัก: `table_display=provider`, `zone=07`, `province_code=46` (กาฬสินธุ์), `year=<ปีงบประมาณ>`
- ฟิลด์ที่ใช้: `a_code`, `a_name`, `targetq1..q4`, `mmr2q1..q4` และ `target` / `mmr2` (ยอดรวมทั้งปี ใช้ตรวจทาน)
- วันที่ข้อมูล: `rows[0].datecom`
- **ปีงบประมาณก่อน 2568 ไม่มีคีย์ `mmr2` ใน payload** (มีแค่ `dtp4`, `opv4`, `je2`, `result4`, `target`) — ดูกับดักข้อ 6

> หัวข้อนี้อธิบายรายงาน **2.1** ที่แดชบอร์ด MMR2 ใช้ · payload เดียวกันมีวัคซีนอื่นครบ
> (`dtp4`, `opv4`, `je2`, `mmr1`, `pcv4`) ซึ่ง**ตอนนี้ถูกใช้แล้วในแดชบอร์ด EPI** (5 เข็มของรายงาน 2.1)
> ส่วน **PCV เข็ม 2 / 4 เดือน และ EPI อีก 17 เข็ม ใช้รายงาน 1.1** (`c88658f4d09acb8c76e6c06ffb58ebaf`)
> — ดูหัวข้อ "แดชบอร์ด PCV" และ "แดชบอร์ด EPI ปกติ" ข้างล่าง

## ⚠️ กับดักที่พิสูจน์แล้ว (อ่านก่อนแก้ script)

สิ่งเหล่านี้เสียเวลา probe มาก่อนแล้ว **อย่าเดาซ้ำ**

### 1. `year` คือ **ปีงบประมาณ** ไม่ใช่ปีปฏิทิน

ปีงบประมาณไทยเริ่ม **1 ตุลาคม** → `ปีงบประมาณ = ปี ค.ศ. + 543 (+1 ถ้าเดือน >= 10)`

- ปีงบประมาณ **2570** = 1 ต.ค. 2569 – 30 ก.ย. 2570
- หลักฐาน 3 ชั้น: (ก) filter ใน UI ของ HDC เขียนว่า "ปีงบประมาณ" (ข) SQL ของรายงานใช้
  `SET @b_year:=(SELECT yearprocess FROM pk_byear LIMIT 1)` แล้ว `b_year=@b_year+543`
  โดยกรอบ cohort คือ `(@b_year-3)-10-01` → `(@b_year-2)-09-30`
  (ค) รายงาน workload เรียงฟิลด์เดือนเป็น `m10, m11, m12, m1 … m9`

### 2. `freeze_month` ต้องเป็น `ALL` เท่านั้น — และ `table_display` ใส่ `district` ไม่ได้

- `freeze_month` เป็นตัวเลข (`1`, `2`, `3`, `12`) → **HTTP 502** ทันที
- `table_display=district` → **HTTP 502** เช่นกัน ใช้ได้แค่ `provider` และ `province`
  (สรุปเป็นรายอำเภอต้อง aggregate เองจากแถวหน่วยบริการ)

### 3. `month` ไม่มีผล

เปลี่ยนค่า `month` แล้ว response **เหมือนกันทุก byte** — อย่าหวังใช้มันกรองรายเดือน

### 4. HDC นับผลงานทันทีที่ฉีด

ข้อความ `notice` ของ HDC ระบุว่านับ **"ไม่ว่าปัจจุบันจะถึงเวลาประเมินหรือไม่"**
ดังนั้นไตรมาสที่ยังไม่จบจะมียอดแล้ว และการบวก `q1+q2+q3+q4` คือยอดทั้งปีที่ถูกต้อง
(กราฟของ HDC เองก็ติดป้ายว่า "ภาพรวมทั้งปีงบประมาณ")

### 5. ปีงบประมาณใหม่จะว่างอยู่พักหนึ่ง

ณ **17 พ.ย. 2569** HDC **ยังไม่มีข้อมูลปี 2570** — ตรวจสอบแล้ว 4 รายงาน ทั้งระดับเขต/จังหวัด/หน่วยบริการ
ครบ 13 เขตสุขภาพ และลองทั้งปี 2570 และ 2571 → ว่างหมด
metadata ของรายงานยังระบุ `byear: "2569"` และมีแม่แบบ PDF แค่ `-2569.pdf`

**นี่เป็นปัญหาต้นทาง ไม่ใช่บั๊กของ repo** — script ออกแบบให้ปี 2570 โผล่เองในเช้าวันแรกที่ HDC เผยแพร่
โดยไม่ต้องแก้โค้ดหรือ workflow แต่อย่างใด

### 6. รายงาน 2.1 เพิ่งเริ่มบันทึก MMR2 ปีงบประมาณ **2568** — ปีก่อนหน้าไม่เอามาแสดง

ดึงปี 2567 และ 2566 มาแล้ว **ไม่มีคีย์ `mmr2q1..q4` / `mmr2` เลย** มีแค่ `dtp4`, `opv4`, `je2`, `result4`, `target`

- ปี 2567 มีเป้าหมายรวม **5,078 คน** แต่ไม่มีผลงาน MMR2 ให้แสดง
- ถ้าบวกคีย์ที่หายไปเป็น 0 แบบตรงไปตรงมา แดชบอร์ดจะขึ้น **0.00%** ซึ่งเป็นการโกหก
- **จึงตัดปีงบประมาณก่อน 2568 ออกทั้งระบบ** — ไม่ดึง ไม่เก็บ ไม่แสดงปุ่มปี (ตัดสินใจแล้วว่ารอดู HDC
  เผยแพร่ปี 2570 มีประโยชน์กว่าการโชว์ปีที่ว่างถาวร)
- `MMR2_FIRST_YEAR = 2568` เป็นทั้ง **จุดแบ่ง** และ **พื้นของช่วงปี**: ต่อให้เพิ่ม `HISTORY_YEARS`
  script ก็ไม่ดึงปีต่ำกว่า 2568 และจะ **ลบ entry ปีเก่าที่ค้างอยู่ในไฟล์** ทิ้งให้อัตโนมัติ

**แนวโน้มข้ามปีจึงเริ่มที่ 2568 → 2569** (90.12% → 97.38%, +7.26 จุด) และจะยาวขึ้นเองเมื่อปี 2570 มีข้อมูล

### 7. บางหน่วยบริการว่างทุกไตรมาส

API ส่งมา 180 แถว แต่มีเพียง **177 (ปี 2569) / 178 (ปี 2568)** แถวที่มีข้อมูลจริง
เช่น `11965` รพ.ธีรวัฒน์ และ `EJA4A` ว่างทุกไตรมาสในทั้งสองปี

- script **ข้ามหน่วยที่ว่างทุกไตรมาส** ทั้งตอนสร้างแถวและตอน cross-check (ต้องข้ามทั้งสองที่ ไม่งั้นจำนวนแถวไม่ตรงกันเอง)
- metadata (อำเภอ / สังกัด / idx) ถูก **merge ข้ามทุกปี โดยปีล่าสุดมาก่อน** เพื่อไม่ให้หน่วยที่ว่างในบางปีสูญเสียอำเภอ/สังกัดไป
- ผลคือปี 2568 เก็บได้ 178 หน่วย ขณะที่ปี 2569 เก็บได้ 177 — **ไม่เท่ากันเป็นเรื่องปกติ**

## รูปแบบข้อมูลใน `dashboard.html`

```js
const HDC_DATA = {
  "2570": { datecom: null, rows: ``, note: "not_published" },
  "2569": { datecom: "15 พฤศจิกายน 2569", rows: `...` },
  "2568": { datecom: "17 พฤศจิกายน 2568", rows: `...` }
};
```

- `note` มีเฉพาะปีที่ไม่มีข้อมูล — ตอนนี้ค่าเดียวคือ `"not_published"` (HDC ยังไม่เผยแพร่)
- ปีที่มีข้อมูลจะไม่มี `note`

แต่ละแถวมี **12 คอลัมน์** คั่นด้วยจุลภาค:

```
idx , district , code:name , agency , t1 , m1 , t2 , m2 , t3 , m3 , t4 , m4
```

- `t<n>` = เป้าหมายไตรมาส n, `m<n>` = ผลงาน MMR2 ไตรมาส n
- **ช่องว่าง = HDC ยังไม่มีข้อมูลของไตรมาสนั้น (`null`)** ต่างจาก **`0` = มีเป้าหมายเป็นศูนย์**
  แดชบอร์ดแสดงป้ายเทา "ไม่มีเป้าหมาย" เมื่อเป้าหมายรวมของ scope นั้น ≤ 0 และตัดออกจากจัดอันดับ/กลุ่มผลงาน
- เรียงแถวตาม `idx` เดิมของหน่วยบริการ (หน่วยใหม่ได้ `idx = 999`)
- ปีล่าสุดอยู่บนสุด · ดึงย้อนหลัง `HISTORY_YEARS = 3` ปี แต่ไม่ต่ำกว่า `MMR2_FIRST_YEAR = 2568`
  (ปีเก่ากว่าที่เคยเก็บไว้ยังอยู่ในไฟล์ ไม่หายไป — ยกเว้นปีก่อน 2568 ที่ถูกตัดออกถาวร)

รูปแบบเดิม (`const rawData = ...`) ยังอ่านได้ — script จะ **migrate ให้อัตโนมัติ** ในรันแรก

### พฤติกรรม UI

- เมนู **"🗂️ ชนิดวัคซีน"** (MMR2 / PCV / EPI / ไข้หวัดใหญ่) เป็นปุ่มกลุ่มแรก สลับข้ามหน้า — ดูหัวข้อเมนูข้างล่าง
- ปุ่มเลือก **ปีงบประมาณ** + **ไตรมาส**; ปุ่ม "ทั้งปี" โผล่เฉพาะเมื่อปีนั้นมี ≥ 2 ไตรมาส
- ตอนนี้มี 3 ปุ่มปี: `พ.ศ. 2568` / `พ.ศ. 2569` / `พ.ศ. 2570 ยังไม่มีข้อมูล`
- ปีที่ไม่มีข้อมูล → ป้ายเหลือง "HDC ยังไม่มีข้อมูลปีงบประมาณ …" + ซ่อนทุกส่วน
  (รวมกริตอำเภอ, KPI, กราฟ, ตาราง, การ์ดแนวโน้ม และปุ่ม CSV)
- **กราฟแนวโน้มข้ามปี** (`#trendChart`) อยู่ระหว่าง KPI กับกราฟแท่ง:
  - เส้นทึบ = ร้อยละความครอบคลุมรายปี, เส้นประส้ม = เป้าหมาย 90% ของ HDC
  - คำนวณใหม่ตาม scope ที่เลือก (ไตรมาส / อำเภอ / สังกัด) — ปีที่เลือกไม่ต้องมีข้อมูลก็ได้ กราฟยังโชว์ทุกปีที่มี
  - ป้าย delta เทียบปีแรก→ปีล่าสุด เช่น `+7.26 จุด จากปี 2568 → 2569` (เขียว = ขึ้น, แดง = ลง, เทา = คงที่)
  - ท้ายกราฟระบุว่าปีไหนถูกข้ามเพราะอะไร
  - ถ้ามีข้อมูลปีเดียว → ซ่อนกราฟแล้วบอก "ยังเทียบแนวโน้มไม่ได้ — รอ HDC เผยแพร่ปีถัดไป"
- อันดับ (rank) คำนวณใหม่**ภายใน scope ปี+ไตรมาสที่เลือก** ไม่ใช่ทั้งจังหวัดแบบตายตัว
- CSV: `MMR2_FY<ปี>_<all|Q1..Q4>.csv`, มี BOM `EF BB BF` ให้ Excel อ่านไทยไม่เพี้ยน,
  export ตาม filter ที่ใช้อยู่ (ไม่ใช่แค่หน้าปัจจุบัน)

## การทำงานของ `sync_hdc_mmr2.py`

1. หา repo dir + git exe เอง (รองรับทั้ง GitHub Actions และเครื่อง Windows)
2. อ่านข้อมูลเดิมจาก `HDC_DATA` (หรือ migrate จาก `rawData`) แล้ว **merge metadata หน่วยบริการข้ามทุกปี**
3. **ตัด entry ปีงบประมาณก่อน 2568** ออกจากข้อมูลเดิม (รายงานยังไม่มี MMR2)
4. ดึง **ปีงบประมาณปัจจุบันย้อนหลัง 3 ปี** (`HISTORY_YEARS = 3`) โดยไม่ต่ำกว่า 2568 — ตอนนี้คือ 2570, 2569, 2568
5. สร้างแถว 12 คอลัมน์ (ข้ามหน่วยที่ว่างทุกไตรมาส) แล้ว **cross-check** กับ API
6. เขียนทับเฉพาะบล็อกข้อมูล (ไม่แตะส่วนอื่นของ HTML)
7. `git add dashboard.html` → commit → push

### กฎการ merge (กันข้อมูลหาย)

| สถานการณ์ | ผลลัพธ์ |
|---|---|
| API ล่ม / `ok: false` | **คงข้อมูลเดิม** ของปีนั้น + นับเป็นความล้มเหลว |
| API ตอบว่าง แต่ของเดิมมีข้อมูล | **คงข้อมูลเดิม** ไม่เขียนทับด้วยศูนย์ |
| API ตอบว่าง และของเดิมก็ว่าง | เก็บ `{datecom: null, rows: '', note: "not_published"}` (ถือว่ารันปกติ ไม่ใช่ error) |
| ปีงบประมาณ < 2568 (ทั้งของเดิมและที่จะดึง) | **ตัดออก** ไม่ดึง ไม่เก็บ ไม่แสดง |
| cross-check ไม่ผ่าน | **คงข้อมูลเดิม** ไม่เผยแพร่ตัวเลขที่รู้ว่าผิด + นับเป็นความล้มเหลว |
| ล้มเหลวบางปี แต่ปีอื่นสำเร็จ | **เขียนปีที่สำเร็จ** คงปีที่ล้มเหลว แล้ว exit 1 |

### cross-check ตรวจอะไร

เทียบ **แถวที่เพิ่งสร้าง** กับข้อมูลดิบจาก API (ไม่ใช่ตรวจ API อย่างเดียว เพราะบั๊กเกิดตอนสร้างแถว):

- ทุกแถวต้องมี 12 คอลัมน์ และทุกช่องตัวเลขต้อง parse ได้
- จำนวนแถว == จำนวนหน่วยบริการที่มี `a_code` **และมีข้อมูลอย่างน้อยหนึ่งไตรมาส**
- ยอดรวม `target` / `mmr2` ในแถว == ผลรวม `q1..q4` ของ API
- ถ้าผลรวมรายไตรมาสของ API ไม่ตรงกับยอดทั้งปีที่ API ให้มา → **เตือน** (ไม่ fail เพราะปีที่ยังไม่ครบ
  ไตรมาสอาจส่งแผนทั้งปีมา)

> บั๊กเดิมของ script คือบวกแค่ `q1+q2+q3` **ทิ้ง q4** ทำให้เป้าหมายหาย 1,085 คน และร้อยละสูงเกินจริง
> 0.65 จุด (แสดง 3,147 / 3,085 / 98.03% แทนที่จะเป็น 4,232 / 4,121 / 97.38%)
> cross-check นี้จับบั๊กนั้นได้ทันที — ทดสอบแล้วเห็นข้อความ
> `API=4232 แต่ในแถวที่สร้าง=3147 (ต่าง -1085)`

### Exit codes

| code | ความหมาย |
|---|---|
| `0` | สำเร็จ (รวมกรณี "ไม่มีอะไรเปลี่ยนแปลง" และ "ปีใหม่ยังว่างใน HDC") |
| `1` | ล้มเหลว: หา repo ไม่เจอ, ไม่พบบล็อกข้อมูล, ไม่มีข้อมูลเลยทั้ง API และของเดิม, **API ล่ม**, **cross-check ไม่ผ่าน**, **git commit/push ล้ม** |

**สำคัญ:** อย่ากลับไปใช้ `except Exception` กลืน error แล้ว exit 0 เด็ดขาด
เพราะจะทำให้ GitHub Actions **เขียวทั้งที่ข้อมูลค้าง** และไม่มีใครถูกแจ้งเตือน
การแยก "ไม่มีอะไรเปลี่ยนแปลง" ออกจาก "commit พัง" ใช้ `git diff --cached --quiet`
(อย่าใช้ `commit.returncode != 0` เพราะ identity หาย / index.lock ค้าง ก็ออก 1 เหมือนกัน)

## GitHub Actions

`.github/workflows/daily_sync.yml` — รันวันละ 3 รอบเผื่อ GitHub ข้าม cron:

| cron (UTC) | เวลาไทย |
|---|---|
| `30 2 * * *` | 09:30 (รอบหลัก) |
| `0 4 * * *` | 11:00 (สำรอง 1) |
| `0 6 * * *` | 13:00 (สำรอง 2) |

- `workflow_dispatch` กดรันเองได้จากแท็บ Actions (รันทั้งสี่ script เสมอ ไม่สน dedupe)
- `concurrency: daily-sync`, `cancel-in-progress: false` กันรันทับกัน
- **step แรกเช็คว่าวันนี้มี commit ที่แตะ `dashboard.html`, `PCVdashboard.html`, `EPIdashboard.html` และ `Fludashboard.html` แล้วหรือยัง**
  แยกธง `skip_mmr2` / `skip_pcv` / `skip_epi` / `skip_flu` ออกจากกัน และมี `skip` (= ข้ามได้ทั้งสี่) นับจาก 00:00 UTC
  → รอบสำรองข้ามเฉพาะตัวที่อัพเดทแล้ว อีกตัวยังรันต่อได้
- `permissions: contents: write`, commit ในนาม `github-actions[bot]`
- Python 3.13 ผ่าน `astral-sh/setup-uv@v5`, `TZ=Asia/Bangkok`
- `sudo apt-get install openvpn` → `python vpn_connect.py` **ครั้งเดียว** แล้วรัน
  `uv run sync_hdc_mmr2.py` → `uv run sync_hdc_pcv.py` → `uv run sync_hdc_epi.py` → `uv run sync_nhso_flu.py`
  (ใช้ VPN connection เดียวกัน · ฝั่ง สปสช. เปิดสาธารณะไม่ต้องพึ่ง VPN แต่รันใน job เดียวกันเพื่อคงตารางเดิม)
- ทั้งสี่ sync step ตั้ง `continue-on-error: true` เพื่อให้ตัวหนึ่งล้มเหลวไม่ตัดอีกตัว
  แต่มี step สุดท้าย `if: always()` ตรวจ `outcome` ของทั้งสี่ แล้ว `exit 1` ถ้ามีตัวใดเป็น `failure`
  → **งานยังแดงถูกต้องเมื่อพังแม้ตัวเดียว** ส่วนกรณีถูกข้าม (skipped) ถือว่าปกติ
- จำลองตรรกะแล้ว: skip 16/16 กรณีถูกต้อง (2^4) · gate 81/81 กรณีถูกต้อง (success/failure/skipped × 4 script)

`vpn_connect.py` ลอง server ไทยสูงสุด 5 ตัว และ `sys.exit(1)` เมื่อต่อไม่ได้ (workflow จึงแดงถูกต้อง)

### ความต่างจาก script MMR2 ที่ตั้งใจให้เป็น

| จุด | MMR2 | PCV | เหตุผล |

| ปีที่ดึง | 2570, 2569, 2568 | 2570 อย่างเดียว | ผู้ใช้เลือกดูปีแรกที่ฉีดเต็มปี |

### พฤติกรรม UI เฉพาะของ PCV

### R-Score — เมนูคะแนนรวมทุกเข็ม (เพิ่มตามคำขอ)

สูตรตรงกับที่ขอ: **ผลรวมของ EPI ทุกชนิด ÷ จำนวนชนิดของวัคซีน × 100**

```
สัดส่วนเข็ม i  = ผลงานเข็ม i ÷ เป้าหมายเข็ม i        (ใช้เป้าหมายของรายงานที่เข็มนั้นสังกัด)
Σ             = ผลรวมสัดส่วนของทุกเข็มที่คำนวณได้
n             = จำนวนเข็มที่คำนวณได้
R-Score       = (Σ ÷ n) × 100
```

**กติกาการคำนวณ (ตั้งใจให้เป็นแบบนี้)**

1. **ระดับหน่วยบริการ** — เฉลี่ยร้อยละของทุกเข็มที่หน่วยนั้นคำนวณได้ · `n` ของแต่ละหน่วยอาจไม่เท่ากัน
   (เช่น ปี 2569 ไตรมาส 1 มีหน่วยที่ได้ 17 เข็ม, 5 เข็ม และ 0 เข็ม)
2. **ระดับอำเภอ / สังกัด / จังหวัด** — รวมเป้าหมายและผลงานของ**แต่ละเข็ม**ทั้งกลุ่มก่อน หาร้อยละของเข็มนั้น
   แล้วจึงเฉลี่ยทุกเข็ม · **ไม่ใช่**การเอาคะแนน R-Score ของหน่วยบริการมาเฉลี่ยซ้ำ
   (หน่วยเล็กที่มีเป้า 1 คนจะไม่ดึงคะแนนจังหวัดเท่าหน่วยใหญ่)
3. **เข็มที่ตัดออก** — HDC ไม่มีข้อมูลในปีนี้ (`indicatorPresent` = false) หรือเป้าหมายเป็นศูนย์/ว่าง
   หรือไม่มีผลงาน → ไม่นับเป็น 0% และ**ไม่เพิ่ม n** · สัดส่วนที่ใช้เป็นค่าเดียวกับโหมดเข็มเดี่ยวทุกประการ
   จึงคลิกเทียบทีละเข็มแล้วเห็นตัวเลขตรงกัน

### ความเร็วตอนกดเข้าเมนูไข้หวัดใหญ่ (แก้แล้ว)

สิ่งที่แก้ (6 ข้อ):

1. **ตรึง URL Chart.js + datalabels ให้เหมือนกันทั้ง 4 หน้า** → ใช้ cache ร่วมกัน ได้ผลมากที่สุด
2. **ย้าย `<script src>` ของ Flu จาก `<head>` ไปท้าย `<body>`** ก่อน inline script → โครงหน้า (หัวข้อ เมนู ป้ายข้อมูล การ์ด 18 อำเภอ) วาดขึ้นจอก่อน ไม่ต้องรอไฟล์กราฟ

### รอบปรับธีมเมนูทั้ง 4 ให้สวยงาม (ทำแล้ว)

โจทย์: เมนูทั้ง 4 หน้าต้องสวยและเข้าชุดกัน โดย**ไม่แตะข้อมูล กราฟ หรือพฤติกรรมเดิม**
ผลคือรวมระบบสีเมนูเหลือ "กฎเดียว + ตัวแปรประจำปุ่ม" และแก้ contrast ที่ไม่ผ่านเกณฑ์ไป 11 จุด

#### 1. ระบบสีใหม่ — ตัวแปรประจำปุ่มแทนกฎซ้ำ 4 ชุด

เดิมปุ่มวัคซีนแต่ละชนิดมีกฎ CSS ซ้ำกัน 4 ชุด (inactive / hover / active / active:hover) × 4 ชนิด = 16 ท่อน
ตอนนี้ตั้งตัวแปรที่ปุ่มครั้งเดียว แล้วใช้กฎกลางคุมทุกสถานะ:

| ตัวแปร | หน้าที่ |
|---|---|
| `--v1` / `--v2` | ต้น/ปลายไล่สีตอน **active** (เข้มพอให้ตัวอักษรขาวผ่าน AA) |
| `--vt` / `--vb` / `--vi` | พื้นทินท์ / ขอบ / หมึก ตอน **inactive** — ทำให้ปุ่มที่ยังไม่เลือกก็จำสีวัคซีนได้ |
| `--vg` | เงาเรืองแสง rgba ตอน hover/active |
| `--vd` (เฉพาะ Flu) | จุด + ขอบ + วงแหวนโฟกัส ซึ่ง**เปลี่ยนตามธีม**ของหน้า Flu |
| `--vt` / `--vi` (เฉพาะ Flu) | พื้นทินท์ + หมึก ตอน inactive **แยกตามธีม** — เพิ่มในรอบเก็บตก ให้ปุ่ม Flu มีสีวัคซีนชัดเท่าอีก 3 หน้า (Flu ใช้ `--vd` เป็นขอบ จึงไม่มี `--vb`) |

|---|---|---|---|---|
